# Catch Me If You Can: จับฉันให้ได้ถ้าคุณกระป๋อง

แพลตฟอร์มตรวจสอบลิงก์ ข้อความ เบอร์โทร และเลขบัญชีที่น่าสงสัย พร้อมตู้เก็บหลักฐานดิจิทัลแบบเข้ารหัส กระดานเตือนภัยจากชุมชน แดชบอร์ดสถิติ และสถาบันฝึกสืบ

## เริ่มใช้งาน

ต้องมี Node.js 18 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm start            # เปิดที่ http://localhost:3000
npm test             # รันชุดทดสอบเซิร์ฟเวอร์ (8 ข้อ)
```

หรือใช้ Docker

```bash
docker build -t cmiyc .
docker run -p 3000:3000 -v cmiyc-data:/app/data cmiyc
```

## โครงสร้างโปรเจกต์

```
public/
  index.html     โครงหน้าเว็บ (5 หน้า: ตรวจสอบ / ตู้เก็บหลักฐาน / กระดานเตือนภัย / ฝึกสืบ / สถิติ)
  styles.css     ธีมไซเบอร์ (โทเคนสีบน :root, โหมดมืดเป็นค่าเริ่มต้น, สลับโหมดสว่างได้)
  app.js         ตรรกะทั้งหมดฝั่งเบราว์เซอร์ ไม่ต้อง build
server/
  server.js      เซิร์ฟเวอร์ Node ไม่มี dependency: static files + REST API ของกระดานเตือนภัย
  server.test.js ชุดทดสอบด้วย node:test
data/            ที่เก็บ db.json ของกระดาน (สร้างอัตโนมัติ)
Dockerfile
```

## ส่วนต่างๆ ใน `public/app.js`

ไฟล์แบ่งเป็นหัวข้อด้วยคอมเมนต์ `/* ==== ... ==== */` ค้นหาตามนี้ได้เลย

| หัวข้อ | หน้าที่ |
|---|---|
| 1) Scam & Phishing Inspector | `BRANDS` รายชื่อแบรนด์และโดเมนทางการ, `analyzeUrl` ตรวจลิงก์, `TEXT_RULES` ตรวจถ้อยคำ, `analyze` รวมคะแนน, `MODES` เกณฑ์เหลือง/แดง 3 ระดับ |
| 2) Digital Evidence Locker | เข้ารหัส AES-256-GCM (กุญแจจาก PBKDF2 250,000 รอบ) เก็บใน IndexedDB, `extractMeta` สกัด SHA-256 / EXIF / ความยาวเสียง / ตรวจนามสกุลไม่ตรงเนื้อไฟล์ |
| 3) Community Alert Board | ฟีดเคส ตัวกรอง ยืนยัน/เบาะแสเพิ่มเติม ใช้ได้ 3 โหมดจัดเก็บ (ดูด้านล่าง) |
| 4) Stats Dashboard | สถิติคำนวณจากเคสบนกระดาน |
| 5) ชั้นนักสืบ | ยศ แต้ม เหรียญ (`awardXP`), แฟ้มคดี (`upsertCase`), ภาพเกิดเหตุ (`sceneHTML`), สถาบันฝึกสืบ (`CASES`) |

## กระดานเตือนภัย: 3 โหมดจัดเก็บ

แอปเลือกโหมดเองตามลำดับนี้

1. **Claude artifact (`db`)** ใช้เมื่อเปิดภายใน claude.ai เท่านั้น
2. **REST API** เมื่อเปิดผ่านเซิร์ฟเวอร์ในโปรเจกต์นี้ ทุกคนที่เปิดหน้าเว็บเห็นเคสร่วมกัน (ดึงข้อมูลใหม่ทุก 12 วินาที)
3. **เครื่องนี้ (localStorage)** ถ้าไม่มีสองข้อบน เคสเห็นเฉพาะในเบราว์เซอร์ของผู้โพสต์

ตั้งค่า base URL ของ API ได้ก่อนโหลด `app.js` เช่นเมื่อแยกโฮสต์หน้าเว็บกับเซิร์ฟเวอร์ (ต้องเปิด CORS เองที่เซิร์ฟเวอร์)

```html
<script>window.CMIYC_CONFIG = { apiBase: 'https://api.example.com/api' };</script>
```

ตั้ง `apiBase: ''` เพื่อปิด REST API และใช้โหมดเครื่องนี้

## ตัวแปรสภาพแวดล้อมของเซิร์ฟเวอร์

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ต (ค่าเริ่มต้น 3000) |
| `DATA_DIR` | โฟลเดอร์เก็บ `db.json` |
| `TRUST_PROXY=1` | อ่าน IP จาก `X-Forwarded-For` เมื่ออยู่หลัง reverse proxy (ใช้กับ rate limit) |
| `ADMIN_TOKEN` | เปิด `DELETE /api/reports/:id` สำหรับผู้ดูแล ต้องส่ง header `X-Admin-Token` |

## REST API

ทุกคำขอส่ง header `X-Client-Id` (รหัสนิรนามสุ่มที่หน้าเว็บสร้างเอง 4-64 ตัว `A-Za-z0-9_-`)

| เมธอด | พาธ | หน้าที่ |
|---|---|---|
| GET | `/api/health` | ตรวจสถานะ |
| GET | `/api/reports` | รายงานล่าสุด 300 รายการ (ไม่ส่ง uid ออกไป) |
| POST | `/api/reports` | โพสต์เคส `{cat, area, title, detail, ident?, author?}` |
| GET | `/api/confirms` | การยืนยันและเบาะแส พร้อมธง `mine` ของผู้เรียก |
| POST | `/api/confirms` | เบาะแสเพิ่มเติม `{rid, kind:'tip', text}` |
| PUT | `/api/confirms/:rid__:clientId` | ยืนยันเคส (หนึ่งคนต่อหนึ่งเคส ทำซ้ำได้ไม่เกิดซ้อน) |
| DELETE | `/api/confirms/:rid__:clientId` | ยกเลิกการยืนยันของตัวเอง |
| DELETE | `/api/reports/:id` | ลบเคส (ผู้ดูแลเท่านั้น) |

การป้องกันที่มีให้: ตรวจรูปแบบและความยาวทุกฟิลด์ ปฏิเสธข้อความที่มีเลข 13 หลักคล้ายบัตรประชาชน จำกัดขนาดคำขอ 16 KB จำกัดเขียน 30 ครั้งและอ่าน 240 ครั้งต่อ IP ต่อนาที เขียนไฟล์แบบ atomic ส่วนหัวความปลอดภัยและ CSP (`script-src 'self'`) และป้องกัน path traversal ฝั่งหน้าเว็บ ทุกข้อความจากผู้ใช้ผ่านฟังก์ชัน `esc()` ก่อนแสดงผล

## ข้อจำกัดที่ต้องรู้ก่อนใช้งานจริง

- **ไม่ได้ต่อฐานข้อมูลภัยคุกคามจริง** การตรวจลิงก์เป็นกฎ heuristic ในเบราว์เซอร์ ผลสีเขียวหมายถึง "ไม่พบสัญญาณผิดปกติ" ไม่ใช่การรับรองความปลอดภัย ถ้าต้องการต่อบริการตรวจ URL หรือรายชื่อบัญชีม้า ให้เพิ่มการเรียก API (ที่คุณมีสิทธิ์ใช้) ในฟังก์ชัน `analyze()` แล้วบวกคะแนนเข้า `out.findings`
- **รายชื่อแบรนด์และโดเมนทางการคัดมือ** (`BRANDS`) ตรวจกับแหล่งสาธารณะบางส่วนเท่านั้น ควรให้เจ้าของระบบไล่ตรวจและปรับปรุงเป็นระยะ
- **ตัวตนของผู้ใช้เป็นแบบนิรนาม** `X-Client-Id` ปลอมได้ จึงกันการยืนยันซ้ำด้วยหลายรหัสไม่ได้ ถ้าต้องการกันจริงจังให้เพิ่มระบบล็อกอิน
- **ไม่มีระบบตรวจเนื้อหาก่อนขึ้นกระดาน** ควรมีผู้ดูแลที่ใช้ `ADMIN_TOKEN` ลบเคสที่เป็นการใส่ร้ายหรือมีข้อมูลส่วนบุคคล และเตือนผู้ใช้ไม่ให้โพสต์ข้อมูลส่วนตัว (หน้าโพสต์มีคำเตือนแล้ว)
- **ตู้เก็บหลักฐานอยู่ในเบราว์เซอร์ของผู้ใช้** ลืมรหัสผ่านกู้คืนไม่ได้ ล้างข้อมูลเบราว์เซอร์แล้วไฟล์หาย และไม่ใช่การรับรองทางกฎหมาย (SHA-256 ยืนยันว่าไฟล์ไม่ถูกแก้หลังเก็บ แต่ metadata ปลอมได้)
- **JSON file เหมาะกับระดับหลักร้อยถึงหลักพันเคส** ถ้าใช้งานหนักให้เปลี่ยน `createStore` เป็นฐานข้อมูลจริง (เช่น SQLite หรือ Postgres) โดยคง interface `db.reports` / `db.confirms` / `save()` ไว้
- **ผ่าน HTTPS เสมอ** ตู้เก็บหลักฐานใช้ Web Crypto ซึ่งต้องการ secure context (localhost ใช้ได้) ให้วางหลัง reverse proxy ที่มี TLS และตั้ง `TRUST_PROXY=1`
- คดีฝึกสืบทั้ง 6 เป็นสถานการณ์สมมติ ใช้โดเมน `.example` และข้อมูลสมมติ ส่วนเคสตัวอย่างบนกระดานติดป้ายและปิดได้
