# Catch Me If You Can: จับฉันให้ได้ถ้าคุณกระป๋อง
## ฉบับตรวจผู้ขายและการซื้อขายออนไลน์

แอปที่ช่วยผู้ซื้อสืบประวัติร้านค้าก่อนโอนเงิน ใส่ข้อมูลผู้ขาย ราคา แชต ลิงก์ และเลขบัญชี แล้วตอบแบบสอบสวน 11 ข้อ ระบบจะไล่สัญญาณเสี่ยงให้ทีละข้อ ทำเครื่องหมายร่องรอยในแชต เทียบกับกระดานเตือนภัยจากชุมชน และบอกว่าเหลืองานสืบอะไรที่ยังไม่ได้ทำ พร้อมตู้เก็บหลักฐานเข้ารหัส เช็กลิสต์ก่อนโอน ขั้นตอนกรณีโอนไปแล้ว และสถาบันฝึกสืบ

## เริ่มใช้งาน

ต้องมี Node.js 18 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm start            # เปิดที่ http://localhost:3000
npm test             # ชุดทดสอบเซิร์ฟเวอร์ 8 ข้อ
```

หรือ Docker

```bash
docker build -t cmiyc-shop .
docker run -p 3000:3000 -v cmiyc-data:/app/data cmiyc-shop
```

## โครงสร้างโปรเจกต์


## ส่วนต่างๆ ใน `public/app.js`

| หัวข้อ | หน้าที่ |
|---|---|
| ตัวตรวจลิงก์ (`analyzeUrl`, `BRANDS`) | ตรวจลิงก์ร้านและลิงก์ชำระเงิน: โดเมนเลียนแบบแบรนด์ 54 แบรนด์ 69 โดเมน, ลิงก์ย่อ, นามสกุลเสี่ยง, ไฟล์ .apk |
| 1) ตรวจผู้ขาย (`investigate`) | รวมคะแนนจาก `QUESTIONS` (แบบสอบสวน 11 ข้อ), `priceWeight` (เทียบราคาตลาด), `TEXT_RULES` (ถ้อยคำในแชต), ตัวระบุที่ตรงกับกระดาน, และสัญญาณที่เกิดร่วมกัน จากนั้นตัดสินระดับด้วย `MODES` (เข้มงวด/มาตรฐาน/ผ่อนปรน) |
| 2) ช่วยเหลือ (`CHECKLIST`, `RECOVERY`, `EVIDENCE`) | เช็กลิสต์ก่อนโอน 10 ข้อ ขั้นตอน 7 ข้อถ้าโอนไปแล้ว และรายการหลักฐาน |
| กระดานผู้ขาย | ฟีดเคส ตัวกรอง ยืนยัน/เบาะแสเพิ่มเติม ครบ 77 จังหวัด ใช้ได้ 3 โหมดจัดเก็บ (ดูด้านล่าง) |
| ตู้เก็บหลักฐาน | เข้ารหัส AES-256-GCM (กุญแจจาก PBKDF2 250,000 รอบ) ใน IndexedDB, SHA-256, EXIF, ความยาวเสียง, ตรวจนามสกุลไม่ตรงเนื้อไฟล์ |
| ชั้นนักสืบ | ยศ แต้ม เหรียญ แฟ้มคดี (เลขคดี โน้ต สถานะ) ภาพเกิดเหตุ (`sceneHTML`) และสถาบันฝึกสืบ (`CASES` 6 คดี) |

### การให้คะแนน

คะแนนความเสี่ยง 0–100 = ผลรวมน้ำหนักของคำตอบในแบบสอบสวน + น้ำหนักราคา (ต่ำกว่า 40% ของตลาด +22, ต่ำกว่า 60% +12, ต่ำกว่า 75% +5) + คะแนนลิงก์สูงสุด + 80% ของคะแนนถ้อยคำในแชต + ผลตรงกับกระดาน (+45 หรือ +60 ถ้าตรงหลายเคส) + โบนัสเมื่อสัญญาณเกิดร่วมกัน ข้อที่ตอบว่า “ยังไม่ทราบ” มีน้ำหนักเล็กน้อยและเป็น “งานสืบที่ยังค้าง” ผลที่ไม่รู้อะไรเลยจึงตกที่สีเหลือง ไม่ใช่สีเขียว ปรับน้ำหนักได้ที่ `QUESTIONS`, `TEXT_RULES` และ `MODES`

ผลตรวจใช้ถ้อยคำ “สัญญาณเสี่ยง” ไม่ตัดสินว่าบุคคลหรือร้านใดโกง เพื่อลดความเสี่ยงด้านการหมิ่นประมาท

## กระดาน: 3 โหมดจัดเก็บ

1. **Claude artifact (`db`)** ใช้เมื่อเปิดภายใน claude.ai เท่านั้น
2. **REST API** เมื่อเปิดผ่านเซิร์ฟเวอร์ในโปรเจกต์นี้ ทุกคนเห็นเคสร่วมกัน (ดึงข้อมูลใหม่ทุก 12 วินาที)
3. **เครื่องนี้ (localStorage)** ถ้าไม่มีสองข้อบน เคสเห็นเฉพาะในเบราว์เซอร์ผู้โพสต์

ตั้ง base URL ของ API ก่อนโหลด `app.js` ได้ เช่นเมื่อแยกโฮสต์ (ต้องเปิด CORS ที่เซิร์ฟเวอร์เอง) หรือตั้ง `apiBase: ''` เพื่อปิด REST

```html
<script>window.CMIYC_CONFIG = { apiBase: 'https://api.example.com/api' };</script>
```

## ตัวแปรสภาพแวดล้อมของเซิร์ฟเวอร์

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ต (ค่าเริ่มต้น 3000) |
| `DATA_DIR` | โฟลเดอร์เก็บ `db.json` |
| `TRUST_PROXY=1` | อ่าน IP จาก `X-Forwarded-For` เมื่ออยู่หลัง reverse proxy |
| `ADMIN_TOKEN` | เปิด `DELETE /api/reports/:id` สำหรับผู้ดูแล (ส่ง header `X-Admin-Token`) |

## REST API

ทุกคำขอส่ง header `X-Client-Id` (รหัสนิรนามสุ่ม 4–64 ตัว `A-Za-z0-9_-`)

| เมธอด | พาธ | หน้าที่ |
|---|---|---|
| GET | `/api/health` | ตรวจสถานะ |
| GET | `/api/reports` | รายงานล่าสุด 300 รายการ (ไม่ส่ง uid ออกไป) |
| POST | `/api/reports` | โพสต์เคส `{cat, area, platform?, title, detail, ident?, author?}` โดย `cat` เป็นหนึ่งใน `noship, notmatch, fake, deposit, mule, phish, other` |
| GET | `/api/confirms` | การยืนยันและเบาะแส พร้อมธง `mine` |
| POST | `/api/confirms` | เบาะแสเพิ่มเติม `{rid, kind:'tip', text}` |
| PUT / DELETE | `/api/confirms/:rid__:clientId` | ยืนยันเคส/ยกเลิกการยืนยัน (หนึ่งคนต่อหนึ่งเคส) |
| DELETE | `/api/reports/:id` | ลบเคส (ผู้ดูแลเท่านั้น) |

ป้องกัน: ตรวจรูปแบบทุกฟิลด์ ปฏิเสธเลข 13 หลักคล้ายบัตรประชาชน จำกัดขนาดคำขอ 16 KB จำกัดอัตราคำขอต่อ IP เขียนไฟล์แบบ atomic ส่วนหัวความปลอดภัยและ CSP (`script-src 'self'`) ป้องกัน path traversal และทุกข้อความจากผู้ใช้ผ่าน `esc()` ก่อนแสดงผล

## ข้อจำกัดที่ต้องรู้ก่อนใช้งานจริง

- **ไม่ได้ตรวจกับฐานข้อมูลภายนอก** ไม่ต่อทะเบียนนิติบุคคล ทะเบียนพาณิชย์ ฐานข้อมูลบัญชีม้า หรือบริการค้นภาพย้อนกลับ ข้อมูลเหล่านี้ผู้ใช้ต้องตรวจเองตามคำแนะนำ “วิธีตรวจ” ในแบบสอบสวน ถ้าต้องการต่อแหล่งข้อมูลที่คุณมีสิทธิ์ใช้ ให้เพิ่มในฟังก์ชัน `investigate()` แล้วบวกคะแนนเข้า `out.findings`
- **ผลขึ้นกับความจริงใจของคำตอบ** ผู้ใช้ตอบผิดหรือไม่ตอบ ผลก็คลาดเคลื่อน ผลสีเขียวไม่ใช่การรับรองร้านค้า
- **รายชื่อแบรนด์และโดเมนทางการคัดมือ** (`BRANDS`) ตรวจกับแหล่งสาธารณะบางส่วนเท่านั้น ควรให้เจ้าของระบบตรวจและปรับเป็นระยะ
- **ตัวตนผู้ใช้เป็นแบบนิรนาม** `X-Client-Id` ปลอมได้ จึงกันการยืนยันซ้ำด้วยหลายรหัสไม่ได้ ถ้าต้องการกันจริงจังให้เพิ่มระบบล็อกอิน
- **ไม่มีระบบตรวจเนื้อหาก่อนขึ้นกระดาน** ควรมีผู้ดูแลที่ใช้ `ADMIN_TOKEN` ลบเคสที่ใส่ร้ายหรือมีข้อมูลส่วนบุคคล และให้ทนายความตรวจนโยบายเนื้อหาก่อนเปิดสาธารณะ เคสที่ระบุชื่อร้านจริงมีความเสี่ยงด้านหมิ่นประมาท
- **ตู้เก็บหลักฐานอยู่ในเบราว์เซอร์ผู้ใช้** ลืมรหัสผ่านกู้คืนไม่ได้ ล้างข้อมูลเบราว์เซอร์แล้วไฟล์หาย และไม่ใช่การรับรองทางกฎหมาย
- **JSON file เหมาะกับระดับหลักพันเคส** ถ้าใช้หนักให้เปลี่ยน `createStore` เป็นฐานข้อมูลจริง โดยคง interface `db.reports` / `db.confirms` / `save()`
- **ต้องใช้ HTTPS** ตู้เก็บหลักฐานใช้ Web Crypto ซึ่งต้องการ secure context (localhost ใช้ได้)
- เคสตัวอย่างบนกระดาน 14 เคสและคดีฝึกสืบ 6 คดีเป็นข้อมูลสมมติ ใช้โดเมน `.example` ติดป้ายและปิดตัวอย่างได้
- ข้อมูลช่องทางแจ้งความ (สายด่วน AOC 1441 และ thaipoliceonline.go.th ซึ่งตำรวจระบุว่าเป็นช่องทางรับแจ้งความออนไลน์เพียงสองช่องทาง) ควรตรวจสอบซ้ำเป็นระยะ ข้อมูลในหน้า “ช่วยเหลือ” เป็นคำแนะนำทั่วไป ไม่ใช่คำปรึกษาทางกฎหมาย
